1.3
===

*In development.* A performance release. The PyTorch transform on a GPU is **18–75x faster** than 1.2 for a single image (forward plus backward) and up to **~500x faster** for batches. Building a transform takes **up to ~13x less time** and uses up to 65% less memory on both backends. The NumPy transform is **1.5–2x faster** without any extra library and up to **7.6x faster** with SciPy installed.

The PyTorch ``UDCT`` is now an ``nn.Module``, the monogenic transform is available in PyTorch, and there are four new gallery examples. For the mechanisms behind the speedups, with diagrams, see :doc:`v1_3_under_the_hood`.

What made it faster
-------------------

Algorithms
^^^^^^^^^^

- **Fused execution plan (torch).** One plan replaces the loop over wedges, so the number of kernel launches no longer grows with the wedge count. (:pr:`84`)
- **No host syncs or per-call casts** on the hot path. (:pr:`83`)
- **Half-spectrum real transform** in torch and NumPy. (:pr:`85`, :pr:`97`)
- **Device-specific folds:** a cache-blocked scatter on CPUs and deterministic gather folds on GPUs. (:pr:`85`)
- **Real-arithmetic gather folds** that apply conjugates on the fly and trace into a single ``torch.compile`` graph. (:pr:`90`)
- **L2-aware batching:** on accelerators, batches whose rows exceed the L2 cache run row by row, which cuts peak memory 2–4x. (:pr:`91`)
- **Native batching:** ``forward``, ``backward``, ``vect`` and ``struct`` accept leading batch dimensions, and ``UDCT.filter(x, fn)`` applies ``fn`` to the flat coefficients between a forward and a backward transform. (:pr:`86`)
- **Sparse window construction** with broadcasts, sparse flips and a thread pool. Torch uses the same builder as NumPy. (:pr:`103`, :pr:`107`, :pr:`114`)
- **Faster NumPy folds** with plain assignment where bins are distinct, cached real weights and one accumulator in the backward transform. (:pr:`97`)

Technologies
^^^^^^^^^^^^

- **CUDA graphs.** ``UDCT(..., cuda_graphs=True)`` records each flat forward and backward once and replays it, including under autograd. (:pr:`92`)
- **Fused Triton fold kernel.** On CUDA the fold runs as one CSR kernel per direction with no atomics, 10–36% faster end to end. (:pr:`94`)
- **torch.compile support.** ``forward_vect`` and ``backward_vect`` compile with ``fullgraph=True``. (:pr:`90`, :pr:`111`)
- **Pluggable FFT engines for NumPy:** ``UDCT(..., fft_engine=None | "scipy" | "numpy" | "auto" | "fftw" | "mkl_fft", fft_workers=None)``. The default is SciPy when it is installed and :mod:`numpy.fft` otherwise. AMD's FFTW is detected at run time, and ``"auto"`` times the installed engines once per shape. New extras: ``curvelets[scipy]``, ``curvelets[fftw]`` and ``curvelets[mkl]``. See :ref:`cpu-performance`. (:pr:`97`)
- **Usable-CPU detection.** Worker counts use the process's CPU affinity rather than ``os.cpu_count()``, and ``fft_workers`` also sets the number of window-building threads. (:pr:`97`, :pr:`114`)

New features
------------

- ``curvelets.torch.UDCT`` is an ``nn.Module`` with adjoint gradients. ``.to()``, ``.cuda()`` and ``.double()`` work, and it can be a submodule. ``forward_vect`` and ``backward_vect`` are public. (:pr:`104`)
- The monogenic transform is available in PyTorch, matching ``curvelets.numpy.UDCT``, with ``UDCT.monogenic()``, batching, CUDA graphs and gradients. (:pr:`111`)
- ``UDCT(..., dtype=...)`` fixes the precision to float32 or float64 at construction, with new ``dtype`` and ``coefficient_dtype`` properties. (:pr:`87`)
- Per-stage GPU profiling tools and a benchmark harness in ``benchmarks/``. (:pr:`81`, :pr:`89`)

New examples
------------

- :ref:`sphx_glr_auto_examples_plot_12_hessian_curvelet_filter.py`: an image-domain inverse Hessian filter in the curvelet domain. (:pr:`66`)
- :ref:`sphx_glr_auto_examples_plot_13_transform_atoms.py`: what a single coefficient looks like for the UDCT, the DWT, the DTCWT and the scattering transform, plus a speed comparison with other libraries in the FAQ. (:pr:`95`)
- :ref:`sphx_glr_auto_examples_plot_14_monogenic_vs_real.py`: amplitude and phase, regularity estimation and local orientation with monogenic and real curvelets. (:pr:`115`)
- ``plot_15_monogenic_fault_detection.py``: synthetic faults and fault zones scored by ROC AUC, testing whether monogenic curvelets detect faults better. (:pr:`116`)

Bug fixes
---------

- ``import curvelets`` failed on Python 3.12 and later after a bare ``pip install curvelets`` because ``typing_extensions`` was imported unconditionally. (:pr:`98`)
- Backpropagation through ``UDCTModule`` failed on CUDA because of a device mismatch in ``struct()``, and ``.to()`` dropped the precomputed index maps so every later call recomputed them. (:pr:`82`)
- A transform loaded onto another device (for example ``torch.load(..., map_location="cpu")`` of a transform that had run on CUDA) failed with a Triton error. The plan is now rebuilt for the new device, and pickling and ``torch.save`` are tested for both backends. (:pr:`109`)
- A real input to the complex PyTorch transform failed in the adjoint path. It now receives the real part, following PyTorch's convention. (:pr:`104`)
- Empty batches no longer crash the row-by-row batch loop. (:pr:`91`)
- Doctest and docstring corrections in the monogenic transform. (:pr:`111`)
- 2-D ``UDCT`` with ``wedges_per_direction >= 6`` reconstructed only to ``~5.6e-9`` instead of machine precision because the auto-selected ``window_overlap`` exceeded the aliasing-free decimation bound :math:`\frac{8}{9}(1 + 2\alpha) \le 1 \iff \alpha \le 1/16`. Auto-selected overlaps are now capped at ``1/16`` (0.0625) in both NumPy and PyTorch, and explicit overlaps that produce non-injective folds emit a warning. (:pr:`123`)
- ``high_frequency_mode="wavelet"`` was not an exact adjoint or Parseval tight frame in NumPy or PyTorch, causing dot-product tests and PyTorch autograd ``gradcheck`` to fail across ``real``, ``complex``, and ``monogenic`` transforms even though round-trip reconstruction succeeded. Symmetric wavelet-scale scaling is now used across both backends, so ``backward`` is the exact adjoint of ``forward``.

Security hardening
------------------

- The PyPI release workflow pins actions to commit SHAs, installs build tools from a hash-locked file, builds without isolation, checks that the built files match the release tag and keeps a read-only token for the build job. (:pr:`100`)
- ``CODECOV_TOKEN`` is no longer available to CI jobs that run third-party code. The test matrix only uploads coverage artifacts, and a separate job with no Python packages uploads them. Workflows use read-only permissions and do not persist credentials. (:pr:`99`)

Upgrading from 1.2
------------------

- **Python 3.11 or newer is required.** Python 3.9 and 3.10 are no longer supported, and 3.15 is added. (:pr:`72`)
- **The PyTorch transform has a fixed precision.** ``UDCT`` is created with ``float32`` unless ``dtype`` says otherwise, and an input of another precision raises a ``TypeError`` that names the fix. Pass ``dtype=torch.float64`` or call ``.double()`` to transform float64 data. (:pr:`87`)
- **Use** ``UDCT`` **instead of** ``UDCTModule``. ``UDCTModule`` still works and emits a ``DeprecationWarning``. ``UDCT(..., transform_kind=k)`` replaces it, and ``forward_vect`` and ``backward_vect`` give the flat layout. (:pr:`104`)
- **Torch window values differ from 1.2 by at most 1.5e-5** (indices are unchanged), because torch now builds its windows in float64 like NumPy. (:pr:`107`)
- **Default** ``window_overlap`` **for** ``wedges_per_direction >= 6`` **is now capped at** ``1/16`` (0.0625) instead of ``0.09`` (for 6) or ``0.16`` (for 12), so default coefficients for ``wedges_per_direction >= 6`` differ from 1.2; ``wedges_per_direction=3`` is unchanged. (:pr:`123`)
- **Wavelet-mode coefficients now form a tight frame.** With ``high_frequency_mode="wavelet"``, the highest-scale wavelet band's forward coefficients are scaled by :math:`1 / \sqrt{2}` in ``real`` and ``monogenic`` modes, and ``complex`` wavelet mode emits a single direction (1 wedge) at the highest scale instead of ``2 * ndim`` duplicate copies.

How these were measured
-----------------------

- **PyTorch on a GPU:** one RTX 4090 pod with both versions in identical environments (torch 2.15.0+cu132, Triton 3.9.0, Python 3.12.3) and the same script. Two interleaved rounds agreed within about 3%.
- **Building a transform:** Intel i7-8565U laptop, Python 3.14.2, NumPy 2.5.5, torch 2.15.0, a fresh process per case, with 10–20% noise.
- **NumPy:** 32 vCPUs of an AMD EPYC 9575F, Python 3.13, NumPy 2.5.5, SciPy 1.18.1, 32 workers.
- Every table holds the other factors fixed unless the feature does not exist in 1.2 (native batching, CUDA graphs and FFT engines).
